Architecture

AI OS is a multi-agent orchestration platform built around three pillars: the Orchestrator, the Agent Fleet, and the Memory Vault. It offers a multi-model routing layer that provides the optimal AI provider for each task.

System Topology

The platform is organized into three vertical layers:

  • Public Layer — Landing page, legal pages, documentation. Accessible without authentication.
  • Authenticated Layer — Dashboard with 16+ views, gated behind Stripe license payment and session cookie.
  • Intelligence Layer — Orchestrator, agent fleet, multi-model routing, and memory vault. Accessed exclusively through the backend API.

Request Flow

When a user initiates a task from the dashboard:

  1. The browser sends an HTTP request to the Express backend
  2. Middleware validates the session cookie and checks rate limits
  3. The Orchestrator (Opus 5 xhigh) analyzes the request and determines which agent(s) to invoke
  4. The effort router selects the optimal effort level (xhigh/high/low) based on task complexity and cost profile
  5. The agent executes, optionally reading from or writing to the Memory Vault
  6. Results stream back via WebSocket for real-time dashboard updates

Effort-Based Model Routing

AI OS consolidates Anthropic models into a single Opus 5 model with effort-based routing, plus external models for specialized roles:

Opus 5 Features

  • 1M token context window — no beta header required, available by default
  • Adaptive thinking — model decides when to reason deeply (no manual budget_tokens)
  • Dynamic Workflows — plans large tasks, fans out to parallel subagents, resumes on interruption
  • Effort controls — xhigh for maximum reasoning, high for balanced, low for fast/cheap
  • Mid-conversation system messages — inject context updates between turns
  • Improved compaction — longer autonomous sessions with better recovery after context compression
  • Better tool triggering — fewer skipped tool calls compared to 4.7

The Orchestrator

The Orchestrator is the central intelligence that decides how to fulfill every request. Running on Opus 5 at xhigh effort (maximum reasoning depth), it:

  • Decomposes complex requests into sub-tasks
  • Selects which agents to invoke and in what order
  • Manages inter-agent dependencies and data handoffs
  • Escalates decisions when confidence is low
  • Synthesizes final outputs from multiple agent results

Memory Vault

The .magent/ directory serves as the persistent memory layer:

  • vault/raw/ — Ingested source documents and data
  • vault/wiki/ — Processed knowledge articles
  • vault/outputs/ — Generated artifacts and deliverables
  • state/ — Runtime state with JSON persistence (auto-saved with debounce)
  • team.yaml — Agent roster, roles, and escalation paths

Frontend Stack

The dashboard is built with vanilla HTML, CSS, and JavaScript — no build tools, no framework dependencies:

  • WebSocket — Auto-reconnect with exponential backoff (max 30s), visual reconnect banner
  • CSS Variables — Centralized design tokens for consistent theming
  • View Router — Hash-based navigation across 16+ dashboard views
  • Inter + JetBrains Mono — Google Fonts for UI and code typography

Frequently Asked Questions

What are the three architectural layers of AI OS?

The Public Layer (landing page, legal pages, documentation, accessible without authentication), the Authenticated Layer (dashboard with 16+ views, gated behind Stripe license payment and a session cookie), and the Intelligence Layer (Orchestrator, agent fleet, multi-model routing, and memory vault, accessed exclusively through the backend API).

How does a request flow through AI OS?

The browser sends an HTTP request to the Express backend; middleware validates the session cookie and checks rate limits; the Orchestrator (Opus 5 xhigh) analyzes the request and picks agents; the effort router selects xhigh/high/low based on task complexity and cost; the agent executes, optionally reading or writing the Memory Vault; results stream back via WebSocket.

What models does AI OS route between?

Opus 5 across three effort tiers (Strategic/xhigh, Professional/high, Scout/low) plus DeepSeek V4 for Economy batch work, Gemini Omni for Creative media, Grok-3 for Realtime data, OpenAI GPT-5.6 for Reasoning, Perplexity Sonar for Grounded Search, Manus for Autonomous multi-step tasks, and Hermes MCP for Persistent background tasks.

What does the Orchestrator do?

Running on Opus 5 at xhigh effort, it decomposes complex requests into sub-tasks, selects which agents to invoke and in what order, manages inter-agent dependencies and data handoffs, escalates decisions when confidence is low, and synthesizes final outputs from multiple agent results.

What is the Memory Vault?

The .magent/ directory: vault/raw/ for ingested source documents, vault/wiki/ for processed knowledge articles, vault/outputs/ for generated artifacts, state/ for debounced JSON runtime state, and team.yaml for the agent roster, roles, and escalation paths.

What is the backend stack built on?

Node.js 20 with Express, WebSocket (ws) with heartbeat for real-time updates, Helmet CSP/CORS/express-rate-limit for security, session cookies plus Bearer token API auth, Stripe Checkout and Webhooks for payments, file-based JSON state with debounced auto-save, and PM2 for process management.
